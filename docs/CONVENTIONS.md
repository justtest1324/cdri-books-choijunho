# CONVENTIONS — 코딩 원칙과 개발 프로세스

> 모든 코드와 PR은 이 문서를 기준으로 작성·리뷰한다.

## 1. 코딩 원칙

### 1.1 데이터 / 계산 / 액션 분리

| 구분 | 정의 | 이 프로젝트에서 | 위치 |
|---|---|---|---|
| 데이터 | 불변 값 | `Book`, 검색 조건, API 응답 타입 | `types/` |
| 계산 | 순수 함수 — 같은 입력이면 같은 출력, 사이드 이펙트 없음 | 가격 포맷팅, 검색기록 FIFO 트리밍, 다음 page 계산, target 매핑 | `utils/` |
| 액션 | 외부 세계와 접촉 | API 호출, localStorage 접근 | `api/`, `lib/` |

- **계산은 액션을 호출하지 않는다.** 예: 기록 트리밍은 순수 함수, localStorage 저장은 호출자(액션) 책임
- 계산이 늘어날수록 테스트가 쉬워진다 — 로직은 최대한 계산으로 밀어낸다

### 1.2 UI와 로직 분리
- 컴포넌트는 "받은 것을 그린다 + 이벤트를 위로 올린다"까지만
- 상태 로직·영속화·API는 훅으로. 훅은 UI를 모른다 (JSX 반환 금지)

### 1.3 단일 책임
- 훅 하나 = 관심사 하나 (`useBookSearch` / `useFavorites` / `useSearchHistory`), 훅 간 import 금지
- 컴포넌트를 한 문장으로 설명할 수 없으면 분리

### 1.4 훅 분리 기준
- 분리한다: (a) 두 곳 이상 사용 (b) 렌더링과 무관한 상태/이펙트 로직이 커질 때 (c) 액션(localStorage 등)을 품어야 할 때
- 분리하지 않는다: 한 곳에서만 쓰는 짧은 로직의 선제적 추상화

### 1.5 사이드 이펙트 경계
- localStorage 접근은 `lib/storage.ts` 한 파일에서만
- fetch는 `api/` 한 곳에서만

### 1.6 선언형 우선 (React는 선언형이다)
- **UI는 상태의 함수**: "무엇을 보여줄지"를 상태로 선언하고, 렌더는 그 상태에서 파생한다 — `isLoading ? <Skeleton /> : <List />`. DOM을 직접 조작해서 화면을 바꾸지 않는다 (ref 명령형 조작은 포커스 이동 등 React가 표현 못 하는 경우만)
- **파생 값은 렌더 중 계산**: 다른 상태에서 계산되는 값을 `useEffect`+`setState`로 동기화하지 않는다. 그냥 렌더에서 계산하거나 `useMemo`
- **useEffect 최소화**: 사용자 이벤트에 대한 반응은 이벤트 핸들러에서 처리. effect는 "외부 시스템과의 동기화"(구독, 관찰자 등록)에만
- **흐름 제어보다 데이터**: 명령형 시퀀스(플래그 세우고 순서 제어) 대신 React Query의 `status`·URL 파라미터 같은 선언적 소스에서 UI를 파생

### 1.7 기타 규약
- 이벤트 핸들러 `handle~`, 콜백 props `on~`
- 파일당 1 컴포넌트, 매직 넘버 상수화 (`MAX_HISTORY = 8`, `PAGE_SIZE = 10`)
- 타입 선언은 `type` 우선 (일관성 목적)
- Tailwind 유틸리티는 디자인 시스템 컴포넌트(`Button`, `Text` 등)에 캡슐화 — 페이지 레벨에 raw 클래스 나열 지양

## 2. 개발 사이클 (이슈 단위)

```
SPEC   이슈의 완료 조건 확인
PLAN   설계 노트 작성 — 컴포넌트/훅/함수 목록, 상태 위치, 원칙 적용 포인트 → 합의
구현    계산·훅: 테스트 먼저 (TDD) / UI: 구현 먼저
검증    ① 자동: tsc + lint + vitest
       ② 시각: 실행 화면을 Figma 캡처와 대조 (UI 이슈의 본검증)
       ③ 리뷰: PR에서 설계 설명 및 이해 확인
반복    검증 실패 시 수정 → 재검증 → 머지
```

## 3. Git / 이슈 / PR 컨벤션

- **커밋**: conventional commits — `feat:` `fix:` `docs:` `refactor:` `chore:` `test:`
- **브랜치**: `feat/{이슈번호}-{요약}` (예: `feat/4-search-bar`)
- **이슈**: 배경 / 완료 조건 체크박스 / 관련 PRD 섹션
- **PR**: 변경 요약 / 설계 결정과 이유 / 원칙 적용 포인트 / UI 변경 시 스크린샷, 본문에 `Closes #N`
- main 직접 커밋 금지 (문서 제외), 이슈 없는 PR 금지
