# PRD — CERTICOS BOOKS (도서 검색 서비스)

> CDRI 프론트엔드 사전과제. 카카오 도서 검색 API 기반 도서 검색 + 찜 관리 웹 앱.
> 상태: **확정 (v1.0)** — 2026-07-07 리뷰 완료. 미확정 사항은 8장의 결정 사항으로 대체됨.

---

## 1. 개요

- 사용자는 도서를 **전체 검색** 또는 **상세 검색**(제목/저자명/출판사)으로 찾고, 결과에서 상세 정보를 펼쳐 보고, **구매 링크로 이동**하거나 **찜**할 수 있다.
- 화면은 **도서 검색**, **내가 찜한 책** 2개 페이지로 구성된다 (상단 GNB 탭 전환).
- 서버는 카카오 도서 검색 API 하나만 사용하며, 찜 목록·검색 기록은 클라이언트(localStorage)에 저장한다.

## 2. 화면 정의

### 2.1 공통 레이아웃
| 요소 | 내용 |
|---|---|
| 헤더 | 좌측 로고 `CERTICOS BOOKS`, 중앙 탭 `도서 검색` / `내가 찜한 책` (활성 탭 밑줄) |
| 콘텐츠 | 중앙 정렬 고정 폭 컨테이너 |

### 2.2 도서 검색 페이지
| 상태 | 구성 |
|---|---|
| 초기(검색 전) | 타이틀 "도서 검색" + 검색바 + `상세검색` 버튼 + "도서 검색 결과 총 **0**건" + 빈 상태(책 아이콘 + "검색된 결과가 없습니다.") |
| 결과 있음 | "도서 검색 결과 총 **N**건" + 결과 리스트(페이지당 10개) |
| 결과 없음 | 초기 화면과 동일한 빈 상태 |

**검색바**
- placeholder: "검색어를 입력하세요"
- Enter 입력 시 검색 실행
- 포커스/입력 시 **검색 기록** 드롭다운 노출 (최대 8개, 초과 시 오래된 것부터 삭제, X로 개별 삭제, 항목 클릭 시 해당 검색어로 재검색, 브라우저 재시작 후에도 유지)

**상세 검색 팝업**
- `상세검색` 버튼 클릭 시 버튼 하단에 팝업(팝오버) 노출, X로 닫기
- 검색 조건 셀렉트: `제목`(기본) / `저자명` / `출판사` + 검색어 입력 필드
- `검색하기` 클릭 시 팝업 닫히고 해당 조건으로 검색 실행
- **전체 검색과 상세 검색은 동시 진행 불가**:
  - 상세 검색 실행 시 → 전체 검색바의 검색어 초기화
  - 전체 검색 실행 시 → 상세 검색 조건 초기화

**결과 리스트 아이템**
- 접힌 상태(기본): 소형 썸네일(+찜 하트) · 제목 · 저자 · 가격 · `구매하기`(Primary 버튼) · `상세보기 ∨`(Gray 버튼)
- `상세보기` 클릭 시 **아코디언 확장**: 대형 썸네일(+찜 하트) · 제목/저자 · "책 소개" 본문 · 우측에 원가/할인가 · `구매하기` (버튼 라벨 `상세보기 ∧`로 토글)
- **찜 하트**: 접힘/펼침 모두 썸네일 우상단에 표시 (Figma 댓글에서 디자이너 확인: "책 이미지 우상단"). 미찜 = `like/line`(라인 하트), 찜 = `like/fill`(#E84118 채움 하트) — Figma 컴포넌트로 확정
- 가격 표기: 할인가(`sale_price`)가 있으면 원가(`price`)는 취소선, 할인가 강조. **할인가 없으면 원가만 노출**
- `구매하기` 클릭 시 새 탭으로 도서 상세 페이지(`document.url`) 이동

### 2.3 내가 찜한 책 페이지
| 상태 | 구성 |
|---|---|
| 초기(0건) | 타이틀 "내가 찜한 책" + "찜한 책 총 **0**건" + 빈 상태("찜한 책이 없습니다.") |
| 목록 있음 | "찜한 책 총 **N**건" + 리스트(검색 결과와 동일한 아이템 컴포넌트, 페이지당 10개) |

## 3. 기능 요구사항

| ID | 기능 | 상세 |
|---|---|---|
| F-1 | 전체 검색 | 검색바에서 Enter 시 `query`로 검색, 페이지당 10개 |
| F-2 | 검색 기록 | localStorage 저장, 최대 8개 FIFO, 개별 삭제, 클릭 시 재검색, 재시작 후 유지 |
| F-3 | 상세 검색 | 팝오버에서 조건(제목/저자명/출판사) + 검색어로 검색. `target` 파라미터 매핑 |
| F-4 | 검색 상호 배타 | 전체↔상세 검색 시 상대편 입력/조건 초기화 |
| F-5 | 결과 리스트 | 총 건수 표시, 아코디언 상세, 가격 표기 규칙, 결과 없음 빈 상태 |
| F-6 | 무한 스크롤 | 페이지당 10개, 스크롤 하단 도달 시 다음 페이지 로드. API `is_end`·`pageable_count` 활용, page ≤ 50 제약 처리 |
| F-7 | 구매하기 | `document.url` 새 탭 오픈 |
| F-8 | 찜하기 | 아코디언 내 하트 토글. **클릭 시점의 도서 데이터 스냅샷을 저장**(API 재조회 없음 → 이후 API 결과와 달라질 수 있음이 명세된 동작). localStorage 저장, 재시작 후 유지 |
| F-9 | 찜 목록 | 찜한 책 페이지에서 조회/해제, 페이지당 10개 |

## 4. API 매핑

`GET https://dapi.kakao.com/v3/search/book` · 헤더 `Authorization: KakaoAK ${VITE_KAKAO_REST_API_KEY}`

| 기능 | 파라미터 |
|---|---|
| 전체 검색 | `query={검색어}&page={n}&size=10` |
| 상세 검색 — 제목 | `query={검색어}&target=title` |
| 상세 검색 — 저자명 | `query={검색어}&target=person` |
| 상세 검색 — 출판사 | `query={검색어}&target=publisher` |
| 총 건수 | 응답 `meta.total_count` |
| 마지막 페이지 판단 | 응답 `meta.is_end`, `meta.pageable_count` (노출 가능 문서 기준) |

**응답 필드 사용처**: `title`(제목) · `authors`(저자) · `contents`(책 소개) · `thumbnail`(표지) · `price`/`sale_price`(가격) · `url`(구매하기·**bookId가 도서 식별 키** — isbn은 중복 사례 존재) · `isbn` · `publisher`, `datetime`, `status`(아코디언 상세에 노출 여부 8장)

**에러/제약**: page 최대 50 → 500건 초과 접근 불가 처리, 401(키 오류)·429(쿼터) 안내 UI, 네트워크 오류 시 재시도 유도.

## 5. 클라이언트 데이터 모델 (localStorage)

```ts
// 검색 기록
key: "certicos-books:search-history"
value: string[]                    // 최신순, 최대 8개

// 찜 목록 — 찜 시점의 Book 스냅샷 (식별자는 getBookKey: url의 bookId → isbn → 제목+출판사 폴백)
key: "certicos-books:favorites"
value: Book[]                      // Book = 카카오 Document 필드 그대로
```

- 서버 상태(검색 결과)는 React Query가 관리, 클라이언트 영속 상태(기록/찜)는 localStorage 동기화 커스텀 훅으로 관리.

## 8. 결정 사항 (2026-07-07 리뷰 확정)

1. **목록 로딩 방식**: **무한 스크롤** — 스크롤 하단 도달 시 다음 10개 로드 (`useInfiniteQuery`)
2. **찜 하트 위치**: **접힘/펼침 모두** 썸네일 우상단 (캡처 재확인 결과 접힌 상태에도 하트 존재)
3. **아코디언 상세 필드**: 캡처에 보이는 것만 — 제목/저자/책 소개/원가/할인가/구매하기
4. **검색 기록 노출**: 검색바 **포커스(클릭) 시** 기록이 있으면 표시, 타이핑 시작하면 숨김
5. **찜 목록 로딩**: 검색과 동일 — 10개 단위 무한 스크롤 (로컬 데이터를 slice하여 동일 UX 제공)
6. **반응형**: 태블릿·모바일까지 대응
   - 데스크톱(≥1024px): Figma/캡처 그대로
   - 태블릿(768~1023px): 컨테이너 폭 유동, 구조 동일
   - 모바일(<768px): 리스트 아이템 세로 스택, 버튼 풀폭, 상세검색 팝업은 하단 시트
7. **로딩 UI** (2026-07-08 확정): 첫 검색 로딩은 리스트 아이템 형태의 **스켈레톤**, 무한 스크롤 추가 로딩은 리스트 하단 스피너
8. **URL 동기화** (2026-07-08 확정): 검색 상태를 URL 쿼리 파라미터로 관리 (`/?q=검색어&target=title`) — 새로고침·뒤로가기·링크 공유 시 검색 결과 유지
9. **엣지 상태** (2026-07-08 확정): 에러 시 "다시 시도" 버튼이 있는 에러 뷰, `thumbnail` 빈 값은 플레이스홀더 이미지, `sale_price === -1`은 할인가 없음으로 처리, 공백 검색어 제출 방지

## 11. 구현 중 추가 결정 (2026-07-08~09, 사용자 QA·코드리뷰 반영)

1. **팝오버 닫기 확장**: 상세검색 팝오버는 바깥 클릭·Esc로도 닫힘 (백드롭 방식, useEffect 없음). '검색하기 시 닫힘'은 명세대로 유지
2. **상세검색 조건 유지**: 팝오버를 다시 열면 활성 조건이 채워져 있음 — 명세의 초기화 조건은 '전체 검색 실행 시'뿐이므로 양립. (조건 칩 방식은 검토 후 폐기)
3. **도서 식별 키**: isbn은 중복 실사례 존재('123 (Flash Cards)' 두 권이 동일 ISBN) → `getBookKey` = url의 bookId → isbn → 제목+출판사 폴백
4. **Figma 실측 보정**: 검색바 480×50, 대형 썸네일 210×280, 펼침 행 344px, 콘텐츠 폭 960px 정중앙 (실측 확인), 검색 기록 행 피치 ~40px
5. **시각 안정성**: Noto Sans KR 셀프호스팅(@fontsource, FOUT 제거), `scrollbar-gutter: stable`(스크롤바 레이아웃 시프트 제거)
6. **재시도 정책**: auth(401/403)·rateLimit(429)은 재시도하지 않음 — 429 재시도는 쿼터 악화
7. **구매하기 시맨틱**: button+window.open → `<a target="_blank">` (Button href 지원)
